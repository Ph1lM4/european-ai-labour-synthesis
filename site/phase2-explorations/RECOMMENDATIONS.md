# Phase 2A — Recommendations

One paragraph per problem. Each names a recommended alternative, what it surfaces best, what it loses, and the build cost. Phil reviews and locks one direction per problem. Phase 2B builds the locked alternatives into the live site in a separate handover.

---

**Problem 1 — Corridor map: Recommend Alternative A (Geographic tile cartogram).** It surfaces the cluster story directly — Nordic green block, Balkan red block, Continental amber band — which the current 4×9 abstract grid loses entirely. It loses the continuous-variation read that B (beeswarm) offers around the corridor edges (1.20 / 2.80) and the accessibility-first reading that C (sortable list) offers; both of those are addressable with secondary supporting elements rather than as the primary view. Build cost is moderate (~3–4 h) — tile positions are hand-coded once, then tiles plug into the existing data-binding pattern. No new tokens or libraries; flag for Phil at lock time: confirm geographic positions before build, particularly micro-states (LU, MT, LI, CY) which sit in geographically-approximate slots rather than topologically-correct ones.

**Problem 2 — Fragility-class graphic: Recommend Alternative B (Population-weighted stack).** It surfaces the count-vs-population asymmetry directly — Class I covers 25.6% of EU-27 working-age pop on 7 markets, Class IV covers 15.7% of 36-market pop on 3 markets — the structurally most useful read, and ties cleanly to the Bundle X aggregates already on `europe.html`. It loses the rule-text-per-class that A (funnel) carries inline, which means the rules need a small companion table or expanded captions in §4 prose; that's a copy-side fix, not a build-side one. Build cost is minor (~2 h) — two stacked bars + segment-width logic + asymmetry callout. No new tokens or libraries; if Phil locks Problem 5 around B (delta-strip primary), the two views form a coherent pair on count-vs-population reading.

**Problem 3 — §3↔§4 cross-linking: Recommend the combined A + B pattern.** Hover-highlight (A) is the discovery layer — no learnable affordance, fires on any pointer movement, teaches the §3↔§4 relationship by showing it. Click-filter (B) is the persistence layer — works on touch, supports sustained reading of one class, and lets readers return to the unfiltered map via Esc or the clear-button. Combining the two costs an extra ~30 min over either alone (one state machine handling transient vs sticky highlight) and creates no conflict; together they cover desktop-discovery and touch-persistence cleanly. Build cost is moderate (~3 h combined). Constraint propagated to Problem 1: each country element must be a focusable button with `data-code` and `data-class` attributes — all three Problem 1 alternatives already meet this constraint.

**Problem 4 — Weather-pattern viz: Recommend Alternative A (Probability-shift small multiples).** It earns the brief's central ask: surface the probability shift across the three regimes (S1 25% → 5%, S2 22% → 30%) directly, with rank inversion as the visual data. B (icon cards) is a real aesthetic upgrade but doesn't tell the shift story — the modal scenario per regime hints at it without making it visible. A loses the calmer, lower-build-cost feel of B and demands slightly more reader effort (three-way visual comparison). Build cost is moderate (~2.5 h) — sorted bars per regime panel + scaled widths + population callouts. No new tokens or libraries; the "shift" summary sentence below the grid uses Phil-locked numbers from data.json.

**Problem 5 — Europe aggregate panels: Recommend Alternative B (Primary view + delta strip).** It aligns with the variation-guard principle already on the live page — variation IS the analytical surface, aggregates are reference points — by foregrounding 36-market as the single primary read and showing the EU-27 "comparison" as a transformation (the deltas) rather than a parallel parallel panel. It loses the visual dramatisation of the subset relationship that A (subset wrapper) provides; that's a real loss, but the delta strip surfaces the same Class IV asymmetry verbally and saves the visual weight of two nested panels. Build cost is minor-to-moderate (~3 h) — delta grid + primary panel reuses the existing aggregate-panel rendering pattern from europe.html. No new tokens or libraries; the delta-item notes use plain conversational copy already implied by the live page's storytelling register, so no new headlines are needed.

## Cross-problem dependencies (read before locking)

- **Problem 3 depends on Problem 1.** Whichever Problem 1 alternative Phil locks must support `data-code` and `data-class` hooks on country elements. All three Problem 1 alternatives do; no constraint conflict.
- **Problem 2 / Problem 5 are mutually-reinforcing.** If Problem 5 locks at B (delta strip + primary), Problem 2 at B (population stack) reinforces the same count-vs-population reading — both views surface the EU-27 / 36 asymmetry, and the page narrative becomes coherent. If Problem 5 locks at A (subset wrapper) and Problem 2 at B, the population stack gets read as duplicating part of the wrapper's delta strip; consider Problem 2 A (funnel) in that combination instead.
- **No new tokens, no new libraries needed across all five recommended alternatives.**
